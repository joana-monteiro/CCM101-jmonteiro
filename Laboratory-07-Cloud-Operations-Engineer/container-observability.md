# Checkpoint 3–5: Container Observability Report

This report describes the deployment of the client's Nginx web server using Docker and the process of monitoring its performance. It covers container deployment, website accessibility testing, application log analysis, and real-time resource monitoring through `docker stats`. These activities help assess the web server's performance under a light workload and establish a baseline for future monitoring.

---

## 1. Deploying the Web Container and Verifying Website Access

I launched the client's Nginx web server in detached mode and assigned the container the name `client-website`. I configured port mapping to connect port `8080` on the host machine to port `80` inside the container.

### Deployment Command

```bash
docker run -d --name client-website -p 8080:80 nginx
```

### Command Explanation

- `-d` — Runs the container in the background.
- `--name client-website` — Sets the container's name to `client-website`.
- `-p 8080:80` — Connects host port `8080` to container port `80`.
- `nginx` — Specifies the official Nginx image used to run the web server.

This command retrieves the Nginx image if it is not already available locally and creates a container that runs the web server.

**Figure 1 — Nginx Container Deployment**

The terminal shows the command used to launch the Nginx container, followed by a container ID indicating that Docker created the container.

### Testing Successful Website Requests

To confirm that the website was accessible, I executed the following command three times:

```bash
curl http://localhost:8080
```

The `curl` command sends an HTTP request to the local web server and displays the server's response. Since Nginx was operating correctly, each request returned the default Nginx welcome page.

**Figure 2 — Successful Website Access Tests**

The terminal displays three requests sent to `http://localhost:8080`. Each request returns the Nginx welcome page, demonstrating that the server can process normal HTTP requests.

### Testing a Nonexistent Web Page

I then tested the server's response to a URL that does not correspond to an existing page:

```bash
curl http://localhost:8080/hidden-admin-page
```

Because the requested resource was unavailable, Nginx returned a `404 Not Found` response. This request provided an example of an application error that could be investigated through the container's logs.

**Figure 3 — Nonexistent Page Request**

The terminal displays the response received after accessing `/hidden-admin-page`. The `404 Not Found` status indicates that the requested resource could not be located on the server.

## 2. Inspecting Application Logs

After performing the website tests, I executed the following command to review the container's log output:

```bash
docker logs client-website
```

This command retrieves the logs generated by the specified container. Depending on the application's logging configuration, the output may contain startup messages and HTTP request records.

**Figure 4 — Docker Application Log Inspection**

The terminal displays the output of `docker logs client-website`, which may include records of successful website requests and the unsuccessful request to `/hidden-admin-page`.

### Sample Error Log

The following example demonstrates how an unsuccessful HTTP request may appear in an Nginx access log:

```text
172.17.0.1 - - [15/Oct/2026:14:22:37 +0000] "GET /hidden-admin-page HTTP/1.1" 404 153 "-" "curl/8.5.0" "-"
```

This entry shows that a client requested `/hidden-admin-page` using the HTTP `GET` method. The server returned status code `404`, indicating that the requested page could not be found.

*Note: Use the actual log entry from your terminal screenshot if the timestamp, client address, or response details differ from this example.*

### Importance of Application Logs in Troubleshooting

Application logs provide valuable information about an application's activities and behavior. They can contain details such as requested URLs, HTTP response codes, timestamps, and client information. Examining these records helps developers and system administrators identify errors, investigate unexpected requests, and resolve technical issues more effectively.

## 3. Monitoring Container Resources in Real Time

To examine the container's resource consumption, I ran the following command:

```bash
docker stats
```

The `docker stats` command continuously displays updated resource statistics for running containers. These statistics include CPU utilization, memory consumption, network traffic, block input/output, and the number of processes.
