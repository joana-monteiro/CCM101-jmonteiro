## 3. Experience and Insights from Mission 10

Mission 10 was among the most challenging activities because it required me to combine several technologies and make them work together in one environment. Compared to the previous activities that focused on specific configurations, this mission required a deeper understanding of how different components interact with each other.

### Docker and Docker Compose

One of the major concepts I learned was how Docker and Docker Compose make application deployment and management easier. Docker provides a way to run applications inside containers together with their necessary dependencies, helping maintain a consistent and organized environment.

Using Docker Compose, I learned how to configure and manage multiple services through a single configuration file. Connecting the application and database containers also helped me understand how different services communicate and work together to support an application.

### Persistent Volumes and Data Storage

Another important lesson from this mission was understanding the purpose of persistent volumes. I learned that keeping important information inside a container alone is not a reliable storage solution because containers can be removed, recreated, or restarted.

Persistent volumes help retain important data even when containers are modified or restarted. This is particularly useful for databases since losing stored information can affect the entire application. Through this activity, I became more aware of the importance of maintaining and protecting data in container-based environments.

### Server Security and UFW Configuration

Server security was another essential part of Mission 10. Configuring UFW (Uncomplicated Firewall) helped me understand how incoming network traffic can be controlled and how access to a server can be restricted.

Setting the default incoming policy to deny and allowing only the required ports showed me the importance of limiting unnecessary network connections. This configuration helps minimize potential security risks and provides additional protection against unauthorized access.

From this experience, I learned that security must be included in the initial planning and development of an infrastructure instead of being considered only after deployment.

### Bash Scripting and Cron Automation

I also gained useful knowledge about automating administrative tasks through Bash scripting and Cron. I learned that repetitive system operations can be handled automatically instead of requiring manual execution every time.

For instance, developing a backup script and configuring Cron to run it on a scheduled basis demonstrated how important system tasks can be performed automatically. This method is useful for maintaining regular backups, organizing files, and managing server operations more efficiently.

This activity helped me understand how automation can minimize repetitive work, improve time management, and make system maintenance more reliable.

### Technical Documentation and Project Organization

Another lesson I gained was the importance of creating clear and organized technical documentation. Preparing the README file, architecture diagram, operational manual, and other project documents helped me understand the role of documentation in infrastructure development.

Well-prepared documentation makes it easier for other users and administrators to understand the system, review its configurations, and follow the necessary procedures for deployment and maintenance. It can also serve as a reference when troubleshooting problems or making future improvements.

## 4. Challenges Encountered and Lessons Learned

While completing the final mission, I experienced several challenges, particularly when working with multiple technologies in a single environment. Since different services rely on one another, even a minor mistake in network settings, container configurations, storage permissions, database connections, or firewall rules can affect the entire system.

These situations taught me to be more careful when troubleshooting technical problems. Instead of making several changes immediately, I learned to identify the possible source of the issue first. This includes checking service statuses, reviewing configuration files, examining error messages, and testing possible solutions one step at a time.

I also discovered that having containers in a running state does not necessarily mean that the entire application is working correctly. Each service still needs to be tested to confirm that communication between components is functioning and that the application can access the resources it requires.

Another important realization was the need for proper preparation before deployment. Security settings, storage management, and backup procedures should already be considered during the planning stage to help maintain a stable and protected environment.

Although some activities required extra time and effort to complete, they helped me develop patience and improve my problem-solving abilities. I learned that encountering errors is a normal part of working with technology, especially when dealing with tools and configurations that are still unfamiliar.
